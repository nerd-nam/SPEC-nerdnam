# ADR-0003: S08 한 줄 진단·갭 대응 가이드를 만드는 곳

- 상태: **결정**
- 날짜: 2026-10-22
- 담당: BE (AI 담당과 함께)
- 관련: 기획서 F5·4.5·5.4·5.5·5.6·S08·8장, 작업목록 FE-12·BE-12·BE-13·AI-07·AI-14, `contracts/화면별-API-목록.md` S08 확인할 것 1

## 배경

S08 적합도 리포트 디자인(`design/report.html`)에는 "한 줄 진단"과 "갭 대응 가이드(가이드 + 하지 말 것)"가 있다. 하지만 기획서 5.5의 `/match` 응답은 판정·근거·이유뿐이라 누가 만드는지 정해지지 않았다.

디자인 예시를 보면 두 요소의 성격이 다르다.

| | 디자인 예시 | 필요한 정보 |
| --- | --- | --- |
| 한 줄 진단 | "필수 3개 모두 근거 경험이 있어요. 결제 승인 API 개선 경험이 가장 많은 요건(3개)을 뒷받침해요." | 판정 개수, 근거별로 뒷받침하는 요건 수 → 저장된 판정 결과로 계산된다 |
| 갭 대응 가이드 | "커머스 결제 경험은 범위를 정확히 밝혀 쓰세요… 하지 말 것: 금융권 경험으로 부풀리기" | 요건 문구, 사용자의 인접 경험, 공고 주요 업무를 읽고 하는 판단 |

## 결정

### 1. 한 줄 진단 — API 서버가 규칙으로 만든다

- 판정 결과(충족·부분 충족·미충족 개수, 근거별 뒷받침 요건 수)로 문장 틀을 채운다. AI를 호출하지 않는다.
- 저장하지 않고 리포트를 조회할 때 계산한다 (충족률과 같은 방식).
- 문장 틀 예: 필수를 모두 충족 / 필수 중 미충족 N개 / 가장 많은 요건을 뒷받침한 경험. 정확한 문구는 FE·기획과 정한다.
- 이유: 숫자로만 이루어진 문장이라 LLM에 맡기면 위 칸 충족률과 다른 말을 할 위험만 생긴다. 규칙이면 항상 일치하고 비용·지연이 없다.

### 2. 갭 대응 가이드 — AI 서버가 `/match`와 다른 프롬프트로 만든다

- 새 엔드포인트 `POST /gap-guide`, 새 프롬프트 **P6 갭 대응 가이드**.
- **시점:** 적합도 분석 작업 안에서 `/match` 직후, **미충족·부분 충족 요건만** 묶어 한 번 호출한다.
- **입력:** 요건 문구·구분·판정, `/match`에서 뽑히지 못한 후보 경험(= 인접 경험) 텍스트와 청크 ID, 공고 주요 업무.
- **출력:** 요건마다 가이드 문장, "하지 말 것" 문장, 인용한 청크 ID. 공통 검증기(AI-04)로 인용 ID와 원문에 없는 수치를 검사한다.
- **프롬프트 규칙:** 없는 경험을 있는 것처럼 쓰라고 하지 않는다. 인접 경험은 입력에 있는 것만 인용한다. 학습 중이면 학습 중이라고 쓰게 한다 (기획서 F5).
- **저장:** API가 요건별 판정 결과(`match_results[]`)에 함께 저장한다.
- **실패해도 리포트는 보여준다.** 갭 가이드만 판정별 기본 문구로 대신한다.
  - 미충족: 가이드 "학습 중이거나 개인 프로젝트가 있다면 '학습 중'으로 따로 적으세요." / 하지 말 것 "사용해 본 것처럼 쓰기"
  - 부분 충족: 가이드 "경험한 범위를 정확히 밝혀 쓰세요." / 하지 말 것 "경험 범위를 부풀리기"
  - GPU 서버가 꺼져 있을 때(ADR-0001)도 같은 처리.
- **작성 방향과 연결:** `/guide`(P4)를 부를 때 저장된 갭 가이드를 입력으로 넘겨, S08과 S09의 조언이 어긋나지 않게 한다.

### 채택하지 않은 안

| 안 | 채택하지 않은 이유 |
| --- | --- |
| `/match`(P3) 응답에 갭 가이드를 같이 넣기 | P3의 규칙은 "근거 밖 추론 금지"인데 조언은 성격이 반대다. 작은 모델(Qwen3.5-4B)에 판정과 조언을 한 번에 시키면 판정 정확도(KPI 85%)가 떨어질 수 있다 |
| `/guide`(P4)에서 만들기 | S08은 작성 방향보다 먼저, 20초 안에 보여야 한다. 작성 방향은 60초가 걸리고 탭을 열 때 만들 수도 있다 |
| 웹 고정 문구만 쓰기 | 디자인 예시가 요건마다 다르다. 고정 문구는 AI가 실패했을 때의 대체 문구로만 쓴다 |

## 영향

| 담당 | 바뀌는 것 |
| --- | --- |
| AI | `/gap-guide` 엔드포인트와 P6 프롬프트 (AI-14), 평가 세트에 갭 가이드 사례 추가 |
| BE | 분석 흐름에 `/gap-guide` 단계 추가, 요건별 판정에 가이드·하지 말 것·인용 근거·생성 출처(AI/기본 문구) 저장, 한 줄 진단 규칙 (BE-12·13) |
| FE | S08 한 줄 진단·갭 가이드 표시, 기본 문구로 대체된 경우 표시 방법 (FE-12) |
| 계약 | `api-ai.openapi.yaml`에 `/gap-guide` 추가 (C-04) |

## 위험

- 리포트 시간이 몇 초 늘어난다(20초 목표). 빠듯해지면 판정을 먼저 보여주고 갭 가이드는 뒤이어 채운다. 웹은 이미 작업 상태 조회(폴링)라 변경이 작다.
