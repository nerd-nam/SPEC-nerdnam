# ADR-0009: AI 작업을 Redis 큐(pull 방식)로 — 한도에 걸리면 실패 대신 가져오기를 대기

- 상태: **제안**
- 날짜: 2026-11-03
- 담당: AI. BE(비동기 전환·trace 전달)·INFRA(큐 Redis·네트워크·대시보드) 검토 필요
- 관련: ADR-0008(실패 대신 대기, "Redis 큐 기각"을 이 ADR이 뒤집음), ADR-0005(클러스터 안 Redis), 기획서 5.5 "메시지 큐는 쓰지 않는다"·8장 리스크 표·v1.65 요청 마감, nerd-nam/INFRA-nerdnam#19(운영 재현 결과)

## 배경

- 지금은 BE가 AI를 HTTP로 동기 호출한다. BE는 AI 작업 스레드 4개로 보내고, 응답이 올 때까지 스레드를 쥔다.
- nerd-nam/INFRA-nerdnam#19 운영 재현(11-03, BE `7eb24db`·AI `7f5f828`) 결과:
  - 두 시나리오 모두 **저하형**. 분석 몰림은 실패 0건, 완료 시간 p50 19초 → 몰림 끝 무렵 약 169초.
  - 병목은 **BE AI 작업 스레드 4개**(두 시험 모두 4개 다 사용, BE 큐 최대 39).
  - 한도에 걸린 재시도로 Bedrock 시도 수가 호출 수의 약 2배(Nova)·1.5~3.7배(Titan).
- ADR-0008은 "한도는 분당 요청 수라 큐를 둬도 처리량은 그대로"라며 Redis 큐를 기각했다. 처리량은 여전히 한도로 고정이지만, 위 결과처럼 **속도를 정하는 곳이 BE 스레드**이고 **재시도로 한도를 낭비**하는 문제는 큐 + 한도기로만 풀린다.

## 결정

**AI가 작업할 수 있을 때 큐에서 가져가 실행하고, 모델 한도에 걸리면 기다린다(pull).**

1. **BE**: 작업 단계를 Redis 큐에 넣고 스레드를 바로 돌려준다. 결과는 BE 소비자가 결과 스트림(`ai:res`)을 읽어 작업 상태(`app.ai_job`)를 갱신한다. 응답을 붙잡고 기다리지 않는다(BLPOP 없음). 분석 단계 순서(추출 → 임베딩 → 검색 → 매칭 → 갭)는 그대로이고, 단계마다 넣고 결과를 받아 다음 단계를 넣는다.
2. **AI 작업자**: 스트림마다 작업자를 둔다. 꺼내는 양은 **작업자 수(동시 처리 상한)** 가 정한다. 시작값은 `llm` 8, `embed` 2, `embed-bg` 1이고 재시험 뒤 조정한다. 처리 로직은 지금 라우터 함수를 그대로 쓴다.
3. **한도기**: 모델별(Titan·Nova) 분당 요청·토큰 한도기를 **Bedrock 호출마다** 적용한다. 메시지 1건이 Bedrock을 여러 번 부를 수 있기 때문이다(`/embed` 1건 = 문장 수만큼 Titan, 최대 32회 / LLM은 응답 형식 오류 때 1회 더). 한도면 자리가 날 때까지 기다린다.
4. **문서 임베딩은 따로**: 확정 후 문서 임베딩(32건씩 최대 20번)은 `ai:req:embed-bg` 스트림에 넣는다. Titan 한도기를 같이 쓰되, 사용자가 기다리는 `ai:req:embed`를 먼저 꺼낸다. 문서 임베딩이 몰려도 분석의 요건 임베딩이 그 뒤에 줄 서지 않게 한다.
5. **큐 대기는 실패가 아니다.** 기한을 두지 않는다. 일시적 오류(throttle·5xx·연결 끊김·AI 파드 재시작)는 재시도·회수(`XAUTOCLAIM`)로 대기에 포함한다. BE `stale-after`(지금 25분)는 **큐에 있는 작업을 정리 대상에서 뺀다**.
6. 진짜 실패(입력 문제, 반복되는 응답 형식 오류, 권한·설정 오류, BE·DB 장애)는 지금처럼 기존 실패 코드로 처리한다.
7. 메시지에 W3C `traceparent`·`enqueued_at`을 넣어 BE → 큐 → AI → Bedrock을 trace 하나로 잇는다.

### 메시지 (C-04에 추가)

| 방향 | 스트림 | 필드 |
| --- | --- | --- |
| 요청 | `ai:req:llm`(Nova: extract·restructure·match·gap-guide·guide), `ai:req:embed`(요건·질의 임베딩), `ai:req:embed-bg`(문서 임베딩) | `id`(작업 id + 단계), `op`, `body`(지금 HTTP 요청 JSON 그대로), `traceparent`, `enqueued_at` |
| 결과 | `ai:res` | `id`, `status`, `body` 또는 `detail`, `usage` |

- `status`(큐 경로): **200** 성공 / **422** 요청 검증 실패 / **502** 모델 오류·응답 형식 오류·설정 오류. 기존 BE 실패 코드 매핑(502 → `ai_error`)을 그대로 쓴다.
- **503·504는 HTTP 경로 전용**이다(대기열 꽉 참·요청 마감). 큐 경로에는 기한이 없어 생기지 않는다.
- 소비자 그룹으로 읽고, 결과를 쓴 뒤 `XACK`. 최소 1회 처리이므로 BE는 작업 id로 결과를 멱등하게 반영한다.

## 측정 (Grafana)

| 지표 | 라벨 | 질문 |
| --- | --- | --- |
| `nerdnam_ai_stage_seconds` 히스토그램 | `model`, `stage`=`queue`·`limiter`·`bedrock` | 이 모델은 어느 단계에서 기다리나 (p95) |
| `nerdnam_ai_queue_lag` 게이지 | `stream` | 이 스트림에 몇 건 밀렸나 |

- 단위: `queue`는 메시지가 꺼내지기까지, `limiter`·`bedrock`은 **Bedrock 호출 1회** 기준. `queue_lag`는 **메시지(작업 단계 1건)** 수다. `embed` 메시지 1건은 Titan을 최대 32번 부르므로, 같은 lag라도 Titan 부담은 다를 수 있다.
- 읽기: `limiter` ↑ = 모델 한도 포화 / `queue`만 ↑ = 작업자 부족 / `bedrock` ↑ = Bedrock 자체 지연.
- trace: AI가 `queue.wait`(시작 = `enqueued_at`)·`limiter.wait`·`bedrock.call` span을 만든다. Tempo에서 작업 1건의 단계별 시간을 본다.
- 끝나지 않는 대기는 밀린 작업이 줄지 않는 모습으로 보인다.

## 검토한 다른 방법

| 방법 | 판단 |
| --- | --- |
| 지금 구조 유지 + BE 스레드만 늘리기 | 한도에 걸린 재시도 낭비는 그대로. 스레드를 늘린 만큼 throttle이 더 난다 |
| AI 한도기만 HTTP 경로에 먼저 | BE 스레드 병목이 남는다. 큐를 바로 적용하기로 함 |
| 세션 Redis를 큐로 같이 쓰기 | 큐가 밀리면 세션 쓰기 실패(256MB, noeviction) = 로그인 장애. 11-03 같은 Redis 메모리 경고가 있었다 → 큐 전용 Redis |
| SQS | 비용은 차이 없다(우리 규모면 월 $1 미만). 유실 방지·가시성 타임아웃(자동 회수)·DLQ를 기본으로 줘서 오히려 유리한 점이 많다. 그래도 Redis를 고른 이유: 로컬 개발·테스트가 `docker run redis`로 끝나고, AWS 권한·Terraform 변경 없이 팀 안에서 빠르게 반복할 수 있고, 클러스터 안 Redis 운영 경험이 있다. 대신 재전달·회수(`XAUTOCLAIM`)·메모리 상한을 직접 만든다. **재전달·유실 문제가 반복되면 SQS로 옮긴다** — 메시지 형식과 측정은 그대로 쓸 수 있다 |

## 남은 위험과 할 일

- **개인정보:** 요청 본문(이력 원문)이 큐 Redis에 머문다. 큐 Redis는 디스크 저장을 끄고, 결과는 짧은 TTL로 둔다. 기획서 8장 "AI 서버는 DB 접근 없음"에 큐 Redis 예외를 적는다.
- **큐 Redis 재시작 유실:** 디스크 저장을 끄므로 재시작하면 메시지가 사라진다. BE가 진전 없는 작업을 다시 넣는다(작업 id 멱등).
- **큐 Redis 메모리:** `noeviction`으로 넘쳐도 작업을 지우지 않는다. 시작 상한 256MB, exporter로 세션 Redis와 같은 메모리 경고를 건다.
- **한도 값:** RPM은 Titan 60·Nova 20(nerd-nam/INFRA-nerdnam#19). TPM은 Service Quotas에서 확인한다.
- **전환:** `AI_QUEUE` 플래그로 HTTP 경로와 병행하고, 안정되면 HTTP 경로를 지운다.
- **기획서·C-04 갱신:**
  - 5.5 "메시지 큐는 쓰지 않는다" 삭제, C-04에 메시지 형식 추가.
  - 8장 리스크 표 "AI 서버·Bedrock 장애 중 요청"(API가 연결 실패·503을 짧은 타임아웃으로 감지해 `GPU_UNAVAILABLE`)을 큐 경로 기준(대기, 일시적 오류는 재시도)으로 고친다.
  - v1.65 요청 마감(읽기 제한 − 10초, 503·504)은 **HTTP 경로 전용**으로 한정한다.
